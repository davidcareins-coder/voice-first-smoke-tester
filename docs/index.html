🎙️ Voice-First Smoke Tester

Does your "voice-first" app actually work by voice? This tester finds out the way a blind user would — by asking it questions and listening for spoken answers.

The problem: developers build voice-first apps, then test them with a mouse and their eyes. That's like testing a wheelchair ramp by walking up it. If the app answers on screen but never speaks, a blind user hears silence — and nobody catches it.

This tester: asks the app questions out loud, checks every answer was spoken, checks answers are announced to screen readers, and checks every feature has a voice path. Then it prints an eyes-closed coverage score.

Latest run — Daily Meds Helper

First target: a voice-first medication helper for an older adult with poor vision. Run Nov 24, 2026: 8 passed, 4 failed, 80% eyes-closed coverage.

✅ Every routine question got a spoken answer.
❌ The answer area has no aria-live — screen-reader users hear nothing when an answer appears.
❌ A failed weekly summary is never spoken — the app only speaks the summary when the cloud AI succeeds.
❌ The label reader has no voice path — it needs a photo from a file picker, which a blind user can't do.

Run it on your app

git clone https://github.com/davidcareins-coder/voice-first-smoke-tester.git
cd voice-first-smoke-tester
npm install
node src/run.js --target https://your-app.example.com --config tests/meds-helper.json --out report

Exit code 0 = no failures. Exit code 1 = the app leaves a blind user stuck somewhere. Report lands in report/report.html.

Write your own question set as JSON: a target URL and questions with the control to click (selector), the words a user would say (spoken), and where the answer appears (answerSelector).
